# Обновление задач, напоминаний и сессий

## Поведение

- Задачи: невыполненные раньше выполненных; внутри каждой группы дедлайны по возрастанию. Совпадающие сроки стабилизированы по ID.
- Просрочка начинается сразу после дедлайна. Выполненная после него задача сохраняет отметку «Выполнена с опозданием · просрочена».
- Отчёты группируют задачи по дате дедлайна, считают все выполненные и отдельно `completed_on_time`, `completed_late`, `overdue_tasks` (ещё не выполненные), `on_time_pct`. Параметр `time_zone` принимает IANA-зону браузера; без него используется зона сервера.
- Настройки напоминаний принадлежат аккаунту. `GET/PATCH /api/v1/reminders/settings`: `event_offsets` и `task_offsets` — массивы минут до начала/дедлайна, каждый до 5 уникальных целых чисел от 0 до 525600. Пустой массив отключает напоминания до срока в соответствующей категории. 0 означает момент начала/дедлайна. По умолчанию оба массива `[60,0]`.
- PATCH изменяет только переданные категории и атомарно пересчитывает будущие напоминания существующих задач и событий.
- Просроченные невыполненные задачи получают напоминание каждые 2 часа. После простоя сервера формируется только актуальный интервал, без очереди всех пропущенных повторений. Выполнение, удаление и перенос задачи удаляют старые напоминания.
- Воркер проверяет очередь каждые 10 секунд. Фактическая доставка push зависит также от соединения устройства, браузера и ОС. Неуспешная доставка повторяется после двухминутной аренды; одинаковые ID уведомлений используют одинаковый tag.
- Профиль представлен компактной строкой с шестерёнкой. Для изменения почты/пароля нужен текущий пароль; после изменения старые refresh-сессии отзываются. После смены данных требуется войти снова.
- Refresh хранится в HttpOnly-cookie. Обновление сериализовано между запросами и вкладками, запись замены и отзыв старого токена выполняются одной транзакцией. Старые регистрации с токеном в localStorage переводятся на cookie при следующем обновлении. Сетевые ошибки и ошибки 5xx не удаляют сессию. `POST /api/v1/auth/logout` отзывает текущий refresh и удаляет cookie.
- При `JWT_REFRESH_TTL=720h` cookie действует 30 дней от входа или последнего обновления. Для требования минимум 14 дней оставьте 720h либо задайте не менее 336h. Access остаётся коротким (`15m`). Для HTTPS включите `SECURE_REFRESH_COOKIE=true`.

## Загрузка и PWA

Фоны WebP сохраняют разрешение 1024×1536, занимают 14–26 КБ вместо 1,3–1,5 МБ. Имена ресурсов содержат хеш, nginx разрешает годовой immutable-кеш. Service worker сохраняет оболочку, JS/CSS и использованные изображения; API и config.js не кешируются. Новая сборка меняет версию кеша. HTML и sw.js проверяются на обновление. Шрифты используют системный стек без отдельного запроса к Google Fonts.

Повторные GET объединяются и кешируются в памяти на 15 секунд; изменения данных и смена аккаунта очищают кеш. Загрузка пользовательского фона уменьшает изображение до 1600px и сжимает перед сохранением. Оболочка доступна без сети, редактирование данных требует соединения.

## Обновление сервера

Сначала сделайте штатную резервную копию базы. В каталоге проекта на сервере:

```sh
git fetch origin
git switch --track origin/codex/reminders-session-ui  # при первом переключении
# если ветка уже существует: git switch codex/reminders-session-ui && git pull --ff-only
docker compose up -d --build
```

Compose применяет миграцию `0010_custom_reminders`. Она создаёт таблицу настроек, добавляет аренду очереди и признак просрочки, устраняет исторические дубли и пересчитывает будущие напоминания на новые значения по умолчанию. Данные пользователей, события и задачи сохраняются. Старые переключатели не имели серверного хранилища, поэтому перенести их индивидуальные значения невозможно.

При rollback кода можно оставить новую схему: добавленные колонки и таблица совместимы с предыдущей версией. Откат самой миграции удалит персональные настройки и очередь повторных уведомлений.

## Проверки

```sh
go test ./...
go vet ./...
go build ./cmd/server
cd frontend
npm ci
npm test       # Node >=22.18 с поддержкой TypeScript type stripping
npm run build
```

`scripts/smoke.py` предназначен только для отдельного локального backend на `127.0.0.1:8089`, PostgreSQL-контейнера `rhythm-check-db`, БД `rhythm_check` (пользователь postgres), с Redis. Требует Docker CLI, создаёт тестовые аккаунты и задачи. Проверяет регистрацию, cookie 14+ дней, повторный refresh, хранение/валидацию настроек, пересчёт очереди, worker просрочки, отчёты, сортировку, остановку уведомлений и logout. Отдельно проверяет 8 конкурентных refresh-запросов.

В ходе разработки проверены Go-тесты, vet, сборки backend/frontend, HTTP API с PostgreSQL 16 и Redis 7, production nginx и его заголовки кеширования, сохранение напоминания и форма профиля в Safari. Реальные push на физических iPhone/Android требуют проверки на HTTPS с production VAPID-ключами.
